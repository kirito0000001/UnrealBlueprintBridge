# UnrealBlueprintBridge 功能文档改版设计

## 目标

根据当前代码实现，完善项目根目录的 `README.md` 与
`AI_GRAPH_PACKAGE_GUIDE.md`，让普通使用者和负责生成图包的 AI/开发者能分别
找到准确、可操作的功能说明。

## 文档分工

### README.md

`README.md` 面向软件使用者和项目开发者，按实际使用流程介绍：

- 项目定位、能力边界和适用场景。
- Unreal 项目工作区与通用草稿工作区的区别。
- GetTheMeaning 数据导入、资产浏览和节点级只读复原。
- 草稿画布、成员编辑、GraphDocument JSON 与本地自动保存。
- 工作区级、资产级和图表级 AI 图例提示词。
- `GraphIndex.json` 图包的生成、导入和示例图包流程。
- Windows 检查更新，以及仅在调试或显式启用时出现的开发者发布工具。

文档提供一条从创建或绑定工作区，到生成提示词、让 AI 写入图包、再导入画布的
完整操作路径。开发环境和构建命令继续保留，但不占据功能介绍的主线。

### AI_GRAPH_PACKAGE_GUIDE.md

`AI_GRAPH_PACKAGE_GUIDE.md` 继续作为图包生成协议，保留现有字段、JSON 示例和校验
规则。在文件开头补充中文快速说明，明确：

- 工作区级提示词用于建立生成约束；草稿工作区在收到具体需求前不得提前写图包。
- 资产/图表级提示词会携带资产路径、父类、图表名、用户需求和执行线摘要。
- 生成结果只能是 `GraphIndex.json` 与 `Graphs/*.json` 视觉草稿。
- 不执行蓝图逻辑，不修改或生成 Unreal `.uasset` 文件。

## 准确性边界

- 只把能够从当前代码、界面文字或测试中确认的功能写成“当前能力”。
- Android 保持为后续目标，不描述为已经完成的正式发布能力。
- GetTheMeaning 的 Widget UI 布局和 C++ 细节跳转仍按现有限制说明处理。
- “制作发布版本”标为开发工具，不作为普通用户功能。
- 不修改 Dart、PowerShell、Unreal 工程或现有未提交代码。

## 验证

- 对照工作区、画布、AI 提示词、图包服务、GetTheMeaning 导入和更新代码复核术语。
- 检查两份文档的相对链接、标题层级和 Markdown 格式。
- 使用 `git diff --check` 检查空白和格式问题，并确认最终差异只包含目标文档与本设计记录。
