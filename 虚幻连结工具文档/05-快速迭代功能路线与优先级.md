# 快速迭代功能路线与优先级

日期：2026-07-07  
目标项目：`D:\UnrealMap\UnrealBlueprintBridge`

## 1. 方向校正

当前阶段不应该继续深入微交互细节，例如按钮状态、chip 标记、局部滚动体验等。

这些体验优化是有价值的，但它们属于第二层级。第一阶段更重要的是快速做出功能闭环，让工具真正能承担“通用节点图 / 蓝图草稿编辑器”的核心用途。

当前优先级调整为：

1. 先做功能闭环。
2. 再做项目管理体验。
3. 再做跨平台适配。
4. 最后系统性打磨视觉和微交互。

## 2. 第一阶段目标：能真正画图

第一阶段应该围绕“用户能自己创建、编辑、保存一张节点图”展开。

优先功能：

- 新建节点。
- 删除节点。
- 编辑节点标题。
- 编辑节点说明。
- 修改节点类型。
- 新增输入 / 输出引脚。
- 删除引脚。
- 创建连线。
- 删除连线。
- 保存当前画布 JSON。
- 加载已有画布 JSON。

这个阶段完成后，即使不依赖 GetTheMeaning，工具也能作为通用节点草稿编辑器使用。

## 3. 第二阶段目标：让 GetTheMeaning 导入成为辅助入口

GetTheMeaning 导入不应该变成唯一入口。它应该是“自动生成草稿”的能力。

优先功能：

- 从蓝图逻辑生成草稿。
- 从某个函数 / 事件切片生成草稿。
- 已有草稿时直接打开。
- 手工编辑导入生成的草稿。
- 保存手工修改，不被重复导入覆盖。
- 支持重置为导入版本。

这样 AI / Unreal 插件导出的数据可以成为起点，而不是限制工具本身。

## 4. 第三阶段目标：项目与文件闭环

优先功能：

- 多项目切换。
- 每个项目保存自己的草稿库。
- PC 端草稿放在 Unreal 项目 `Saved` 目录下。
- Android 端草稿放在应用自己的工作区目录。
- 支持独立导入 / 导出 `.json` 图文件。
- 支持最近打开项目。
- 支持打开草稿所在目录。

这一步完成后，工具才更像一个真正可持续使用的工作台。

## 5. 第四阶段目标：Android 可用

Android 不应该只是能启动，而是要能完成核心编辑。

优先功能：

- 触控拖拽节点。
- 双指缩放画布。
- 触控平移画布。
- 底部抽屉编辑节点属性。
- 底部抽屉选择草稿。
- 手机端保存 / 加载草稿。

PC 独有能力，例如启动 Windows EXE、和 Unreal Editor 通信，放到后面。

## 6. 暂缓的细化项

以下内容暂缓，不作为接下来几步的主线：

- chip 上显示“已有画布”状态。
- 更复杂的滚动动画。
- 大量视觉动效。
- 更细的苹果风界面拟态。
- 编辑器左栏和底部抽屉的最终布局打磨。
- 图标和色彩的精修。

这些应该等核心功能跑通之后再统一整理。

## 7. 下一步建议

下一步建议做“画布手工编辑 MVP”：

- 让 `新增节点` 按钮真正创建节点。
- 选中节点后右侧检查器可以编辑标题、说明和类型。
- 支持删除选中节点。
- 修改后自动保存到当前草稿。

这一小步完成后，用户就能开始把导入生成的图改成自己的草稿，而不是只能查看。

## 8. 2026-07-07 进展：画布手工编辑 MVP 第一版

已完成第一版手工编辑能力：

- 从节点类型列表点击创建节点。
- 新节点会自动选中，并触发当前草稿保存链路。
- 右侧检查器支持编辑节点标题。
- 右侧检查器支持编辑节点说明。
- 右侧检查器支持修改节点类型。
- 支持删除当前选中节点。
- 删除节点时会同步删除与该节点相关的连线。
- 支持添加输入引脚。
- 支持添加输出引脚。
- 支持删除引脚。
- 删除引脚时会同步删除与该引脚相关的连线。
- 支持从输出引脚到输入引脚创建连线。
- 支持删除连线。

当前限制：

- Android / 窄屏端目前只接入了新增节点，检查器编辑还没有做成底部抽屉。
- 引脚只能新增 / 删除，还不能编辑名称、类型和多连线规则。
- 连线创建目前通过检查器里的下拉框完成，还不是直接在画布上拖线。
- 节点尺寸还不是用户可调。
- 没有撤销 / 重做。

这一步的价值：

- 工具已经不只是查看 GetTheMeaning 导出的蓝图逻辑。
- 用户可以开始手工修改导入生成的草稿。
- 手工编辑会走当前 `onDocumentChanged` 和草稿自动保存链路。

下一步建议改为“文件保存 / 加载闭环”：

- 支持从工具内新建空白草稿。
- 支持把当前草稿导出为独立 JSON 文件。
- 支持从 JSON 文件导入为新草稿。
- PC 端可以先保存到当前工作区目录。
- Android 端后续再接文件选择器。

这比继续打磨节点编辑 UI 更符合快速迭代主线。

## 9. 2026-07-07 进展：文件保存 / 加载闭环第一版

已完成第一版草稿文件闭环：

- 顶栏新增 `草稿` 菜单。
- `新建空白草稿`：创建一张手工空白图并进入画布。
- `导出当前画布 JSON`：把当前激活草稿导出为独立 JSON 文件。
- `导入最新 JSON 草稿`：从当前工作区的导出目录读取最新 JSON，并作为新草稿打开。
- 概览页显示 `草稿 JSON` 目录，方便找到导出的文件。
- 导出的 JSON 继续使用 `GraphJsonCodec`，与内部图数据结构一致。

当前导出目录规则：

- 文件会保存到应用数据目录下的 `graph_exports_<workspaceId>` 文件夹。
- 文件名会做安全化处理，避免路径符号导致写入失败。

当前限制：

- 还没有系统文件选择器。
- 导入暂时读取“当前工作区导出目录里的最新 JSON 文件”。
- Android 后续需要接应用私有目录和文件选择器。
- 顶栏 `保存工作区` 按钮还没有做成显式 flush / 保存反馈。

下一步建议：

- 做“显式保存工作区”按钮，让用户能手动 flush 当前草稿状态。
- 或者做“草稿管理页”，集中显示所有手工草稿、导入草稿、导出路径和最近修改时间。

从大方向看，更推荐下一步做“草稿管理页”，因为现在已经有多个草稿来源：GetTheMeaning 生成、手工新建、JSON 导入。需要一个地方统一看清楚。

## 10. 2026-07-08 进展：服务幻杀对局蓝图改造的图包验证

当前工具已经开始用于辅助 `D:\UnrealMap\FantasyProject` 的实际蓝图逻辑讨论，而不只是独立画布测试。

本次已生成并验证可解析的 GraphIndex 图包：

- `D:\UnrealMap\FantasyProject\Saved\BlueprintBridge\GraphIndex.json`
- `D:\UnrealMap\FantasyProject\Saved\BlueprintBridge\Graphs\GM_PtoP_VerifiedLoginFlow.json`
- `D:\UnrealMap\FantasyProject\Saved\BlueprintBridge\Graphs\GM_PtoP_CharacterSelectFlow.json`

这两张图用于辅助当前幻杀第一版对局闭环：

- `GM_PtoP / Verified Login Flow`：说明服务器应维护已验证玩家列表，替代 `GetNumPlayers` 和 `GetPlayerController(Index)`。
- `GM_PtoP / Character Select Flow`：说明选人请求应从 UI 到 PC，再由 Server RPC 进入服务器校验，最后写入 `PS_PtoP.SelectChar`。

接下来很可能需要围绕真实使用场景改工具，而不是单纯补视觉效果。

优先改进方向：

- GraphIndex 导入后应清楚显示图包来源路径、图数量、图标题和导入时间。
- 草稿列表中应能区分手工草稿、JSON 导入草稿、AI 生成图包草稿、GetTheMeaning 生成草稿。
- 每张草稿最好显示 `assetName`、`assetPath`、`graphName`，方便和 Unreal 蓝图资源对应。
- 导入 GraphIndex 后，最好允许一次性导入全部图，也允许只选择其中几张图导入。
- 节点说明需要更容易阅读，当前蓝图逻辑讨论会大量依赖节点说明而不是只有标题。
- 连线标题和说明需要能显示 / 编辑，方便标注 True / False / LoopBody / Completed 等流程含义。
- 需要撤销 / 重做，防止手工整理蓝图逻辑时误删节点或连线。
- 需要更稳定的显式保存反馈，避免用户不知道当前草稿是否已经写入磁盘。
- 后续如果要边看边改 Unreal 蓝图，工具需要快速刷新 / 重新导入同一图包，并尽量保留手工调整过的位置和注释。

当前更推荐的下一步：

1. 先做“草稿管理页”，集中展示所有草稿来源和元数据。
2. 再做“GraphIndex 导入选择器”，不要只靠最新 JSON。
3. 再做“节点说明与连线说明的可读性增强”。
4. 最后补撤销 / 重做和更舒服的画布编辑。

这轮工具修改的目标不是让它变成完整 Unreal 蓝图编辑器，而是让它成为“蓝图逻辑讨论、AI 生成流程草稿、人工修正方案”的工作台。

## 9. 2026-07-07 进展：引脚和简化连线编辑 MVP

已完成：

- 检查器里可以给选中节点添加输入引脚。
- 检查器里可以给选中节点添加输出引脚。
- 新增引脚会立刻写入当前 `GraphDocument`。
- 新增引脚会在画布节点上显示。
- 可以删除某个引脚。
- 删除引脚时会同步清理使用该引脚的连线。
- 检查器里新增了简化连线创建器。
- 连线创建器可以从所有输出引脚里选择起点。
- 连线创建器可以从所有输入引脚里选择终点。
- 创建后的连线会进入 `GraphDocument.links` 并显示在画布上。
- 当前节点相关连线会列在检查器中，并提供删除按钮。

当前实现取舍：

- 第一版没有做拖拽接线，先用检查器下拉框创建连线。
- 第一版没有做 pin 标题 / 数据类型编辑，只做新增和删除。
- 第一版没有做连线标题 / 说明编辑。
- 第一版不做复杂类型校验，只根据 exec pin 简单决定连线类型。

下一步建议继续补“文件闭环”或“撤销重做”：

- 如果走文件闭环：做独立 `.json` 图文件导入 / 导出。
- 如果走编辑体验闭环：做撤销 / 重做，避免手工编辑时误删节点或连线。

这两个都比继续做界面细节更符合当前快速迭代阶段。
