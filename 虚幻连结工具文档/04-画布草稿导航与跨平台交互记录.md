# 画布草稿导航与跨平台交互记录

版本：0.1  
日期：2026-07-07  
目标项目：`D:\UnrealMap\UnrealBlueprintBridge`

## 1. 本轮目标

当前工具已经能从 GetTheMeaning 导出的蓝图逻辑里生成画布草稿，但同一个蓝图可能会出现多张不同用途的图，例如：

- `LB_Fucs / 全部执行线`
- `LB_Fucs / 某个函数`
- 旧单画布缓存迁移来的草稿

如果只看图名，用户很难判断当前选中的是哪一张。这个问题在 PC 上可以靠左侧栏缓解，但 Android 端没有足够空间长期显示左侧栏，所以需要一个跨平台都能用的画布草稿入口。

## 2. 设计决定

不把“画布草稿”放进 Windows 顶栏菜单。

原因：

- 顶栏菜单是桌面端思路，Android 上没有对应形态。
- 画布草稿是高频切换对象，不应该藏得太深。
- 后续触控端需要更大点击目标和更明确的当前状态。

本轮采用的设计：

- 宽屏 / PC：左侧保留“画布草稿”列表，用于稳定浏览和切换。
- 窄屏 / Android：不显示左侧草稿栏，用右下角浮动“画布导航”入口打开底部抽屉。
- PC 端也保留右下角浮动入口，方便形成统一习惯。
- 草稿卡片显示 `资产名 / 图名`，下面显示 `AssetPath` 或 `旧单画布缓存`。
- 当前草稿用紫色边框、左侧竖条和 `当前` 标记一起强调。

这个模式参考了跨平台工具常见的布局原则：大屏使用 sidebar 承载稳定导航，小屏使用 sheet / bottom sheet 承载临时选择。后续如果做 Android，直接复用底部抽屉即可。

## 3. 当前实现

主要代码位置：

- `lib/features/editor/editor_page.dart`
- `test/features/editor/editor_page_test.dart`

已经实现：

- `_CanvasDraftsPanel`：宽屏左侧草稿列表。
- `_CanvasDraftTile`：草稿卡片，区分同名图的来源路径。
- `_FloatingCanvasNavigator`：右下角浮动入口。
- `showModalBottomSheet`：跨平台草稿选择抽屉。
- `重置当前画布`：放在抽屉底部，避免误触。
- 紧凑屏测试：验证窄屏默认不显示左侧草稿栏，而是显示浮动入口。

本轮修复：

- 浮动入口从透明 `GestureDetector` 改为 `Material + InkWell`，提高桌面和触控的命中稳定性，并保留点击反馈。
- 测试中在关闭底部抽屉后等待动画稳定，再验证第二次打开和重置操作。

## 4. 用户可测试点

可以用以下方式检查：

- 选中一个有多张草稿的蓝图，确认左侧列表能看到 `资产名 / 图名` 和来源路径。
- 点击右下角“画布导航”，确认底部抽屉能打开。
- 在抽屉里切换另一张草稿，确认当前画布变化。
- 再打开抽屉点击“重置当前画布”，确认只重置当前草稿，不创建新草稿。
- 把窗口缩窄到接近手机宽度，确认左侧草稿栏消失，但右下角浮动入口仍可用。

## 5. 下一步建议

下一步建议做“项目 / 资产 / 草稿”的分层导航沉淀：

- 顶层：工作区项目列表。
- 中层：资产树，按路径、类型、蓝图类分组。
- 右侧或抽屉：当前资产下的草稿页。

这样同一个蓝图的不同图不会像重复项，而会变成“某个资产下面的多张草稿”。这也更接近未来 PC 和 Android 都能理解的项目管理结构。

## 6. 2026-07-07 进展：资产下草稿页

已完成“三层导航”的第一步：

- `BlueprintAssetsView` 支持接收当前 `CanvasWorkspace` 里的草稿列表。
- 资产详情页会筛选当前资产的草稿，只显示属于这个 `AssetPath` 的画布。
- 草稿区显示为 `画布草稿`，右侧显示数量，例如 `2 张`。
- 草稿以 chip 形式展示，例如 `全部执行线`、`UserLogin`。
- 当前正在编辑的草稿会显示 `当前` 标记。
- 点击某张草稿会通过 `onCanvasDraftSelected` 进入画布编辑页。

这一步解决的问题：

- 同一个蓝图有多张图时，不再只是编辑器左侧的一串列表。
- 用户在资产详情里就能看到“这个蓝图已经有哪些画布草稿”。
- `PC_Main` 的草稿不会混入 `GM_MainMode` 的资产详情。

当前仍保留：

- 编辑器左侧草稿列表。
- 右下角浮动画布导航。

后续可以继续把编辑器左侧列表弱化，逐步让“资产详情里的草稿页”成为主要入口。移动端则可以把这个区域换成底部抽屉或资产详情里的横向滚动 chip。

## 7. 2026-07-07 进展：逻辑切片与草稿动作联动

已完成切片级操作联动：

- “查看画布”按钮从资产标题右侧移动到“逻辑深读 / 切片选择”区域下方。
- 用户先选择 `全部`、`UserLogin`、`EventGraph` 等切片，再对当前切片执行画布操作。
- 如果当前切片已经有草稿，按钮显示 `查看画布`。
- 点击 `查看画布` 会直接打开已有草稿，不重新生成。
- 如果当前切片还没有草稿，按钮显示 `创建画布`。
- 点击 `创建画布` 会按当前切片的执行线生成草稿并进入画布。

当前图名映射规则：

- 逻辑切片 `全部` 对应草稿图名 `全部执行线`。
- 其他切片直接使用切片的 `graphName`，例如 `UserLogin`。

这一步的价值：

- 避免用户误以为每次点击都会创建一张新图。
- 让“已有草稿”和“需要生成”的状态一眼可见。
- 操作按钮贴近切片选择和执行线预览，符合“选中上下文后操作”的交互习惯。

## 8. 2026-07-07 进展：滚动过渡优化

已完成第一轮滚动体验优化：

- 新增全局 `BridgeScrollBehavior`。
- Windows / Android 共用同一套滚动行为。
- 支持 touch、mouse、trackpad、stylus 拖拽滚动。
- 全局滚动物理改为带边界过渡的 `BouncingScrollPhysics + AlwaysScrollableScrollPhysics`。
- 资产树列表和资产详情页加入显式滚动条。
- 选择逻辑切片后，会用 `Scrollable.ensureVisible` 平滑定位到当前切片的画布操作按钮。
- 平滑定位动画为 360ms，曲线为 `easeOutCubic`。

这一步解决的问题：

- 长资产详情滚动时不再完全没有反馈。
- 切换切片后，操作区不会生硬跳动。
- 桌面端鼠标、触控板和未来 Android 触控端的滚动入口更统一。

后续还可以继续优化：

- 给编辑器里的草稿列表、底部抽屉列表也统一接入更精细的滚动体验。
- 如果桌面滚轮仍觉得“一格一格”，可以进一步做自定义平滑滚轮控制，但要避免和 Flutter 默认 `Scrollable` 的 pointer signal 处理叠加。
