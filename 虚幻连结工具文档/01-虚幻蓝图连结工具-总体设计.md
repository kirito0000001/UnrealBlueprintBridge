# 虚幻蓝图连结工具 - 总体设计

版本：0.1  
日期：2026-07-07  
目标项目：`D:\UnrealMap\UnrealBlueprintBridge`

## 1. 定位

这个工具暂定名为“虚幻蓝图连结工具”。它不是直接替代 Unreal 蓝图编辑器的节点编辑器，也不在第一版直接生成或修改 `.uasset`。

它的第一定位是一个“蓝图草图桥梁”：

- 你可以用 WinUI 画出一段蓝图逻辑的大概结构。
- Codex / AI 可以读取这个草图的 JSON，稳定理解你的意图。
- Codex / AI 也可以把分析结果写成同一套 JSON，再由工具显示成图。
- GetTheMeaning 插件导出的蓝图 JSON 可以导入进来，转成更容易看的简化逻辑图。
- 草图可以导出 Markdown / Mermaid / JSON，方便粘贴给对话、写文档、做重构计划。

一句话：它是“蓝图逻辑的可视化中间层”，不是 UE 蓝图资产的直接编辑层。

## 2. 为什么先做独立 WinUI 工具

直接在 Unreal 里让 AI 自动连节点会遇到几个风险：

- `.uasset` 不是普通文本，直接写入风险高。
- 蓝图节点生成、Pin 类型、默认值、宏、局部变量、函数图、事件图都有上下文约束。
- 编辑器脚本可以辅助创建节点，但第一版如果追求全自动，很容易出现“看起来生成了，实际语义不对”的问题。
- 你现在更需要的是让 AI 准确读懂逻辑、指出风险、解释分支和连线，而不是立刻自动替你改蓝图。

所以第一版应该走安全路径：

1. 独立 WinUI 画布。
2. 保存稳定的 `SketchLogic.json`。
3. 导出人类可读 Markdown 和 Mermaid。
4. 导入 GetTheMeaning 的蓝图 JSON。
5. 后续再接 Unreal 插件按钮，例如“在连结工具中打开导出结果”。
6. 更后面才考虑 Editor Utility 半自动创建蓝图节点。

### 3.1 WinUI 工具箱规范

本工具归入现有工具箱体系，基础 UI 和工程结构遵守 `C:\Users\liuyu\Desktop\WinUI工具箱制作文档`：

- Mica 背景。
- 48px 自定义顶栏。
- 左侧 `NavigationView` 大栏位。
- 内容区平铺可用宽度。

- 长操作走底部全局进度条。
- 短反馈走右上角 Tips。
- 页面持续状态走通告栏。
- 确认、输入、选择走统一 DialogService。
- 导出、导入、批量处理这类文件操作要走 Service，并考虑备份 / 回滚。

### 3.2 思维导图参考

亿图脑图 / EdrawMind 类工具最值得参考的是交互形态，而不是主题模板：

- 自由画布。
- 节点和连线可以快速组织结构。
- 能在图和大纲之间切换。
- 支持备注、附件、导出。
- 支持把外部文档或结构化内容转成图。
- 支持 AI 生成大纲、总结或导图。

对本工具的转译是：

- 中心不是“漂亮导图”，而是“蓝图执行流和数据流”。
- 节点需要保留 Unreal 语义：Event、RPC、Branch、Function Call、Set Variable、Loop、Return 等。
- 画布旁边必须有结构化大纲和 JSON 预览，方便 AI 和人双向确认。
- 导出格式比视觉效果更重要。

## 4. 第一版范围

第一版建议做成“手动画图 + JSON/Markdown 导出 + 基础导入”的工作台。

### 4.1 必做

- 新建 / 打开 / 保存草图文件。
- 画布支持平移、缩放、选择、拖动节点。
- 从左侧节点库添加节点。
- 节点之间创建执行线和数据线。
- 右侧属性面板编辑节点标题、类型、参数、默认值、备注。
- 输出 `Sketch_Logic.json`。
- 输出 `Sketch_Readable.md`。
- 输出 Mermaid 流程图草案。
- 支持从 GetTheMeaning 的 `*_Logic.json` 导入成简化图。
- 支持从工具导出的 `Sketch_Logic.json` 再打开。

### 4.2 第一版暂不做

- 不直接修改 `.uasset`。
- 不承诺完全复刻 UE 蓝图编辑器视觉。
- 不做完整 Blueprint 编译器。
- 不做复杂自动布局的高级算法，只做可用的分层排列。
- 不把所有 UE 节点类型都做完，只覆盖最常见逻辑节点。

## 5. 主界面设计

主界面遵守工具箱规范，但内容区是一个长期工作区，不是营销页。

### 5.1 左侧一级导航

建议左侧 `NavigationView` 第一版有这些入口：

- 草图工作台
- 导入导出
- 模板 / 节点库
- 检查结果
- 整体设置

其中“整体设置”固定放在 Footer。

### 5.2 草图工作台

草图工作台是主页面，布局建议：

- 顶部工具行：新建、打开、保存、导入、导出、复制 JSON、复制 Markdown、自动布局、缩放归位。
- 左侧节点库：常用蓝图节点类型。
- 中央画布：节点和连线。
- 右侧属性面板：当前选中节点 / 连线 / 画布的属性。
- 底部或右下输出区：大纲、JSON、Markdown、Mermaid、风险提示的 Tab。

画布要尽量铺满，不把主要工作区塞进装饰卡片。节点本身可以是小面板，但不要卡片套卡片。

### 5.3 节点库

第一版节点库建议包含：

- Event
- RPC Event
- Function Call
- RPC Call
- Branch
- Sequence
- Set Variable
- Get Variable
- ForEachLoop
- ForEachLoopWithBreak
- Return
- CreateWidget
- AddToViewport
- Comment Group
- Note

后续可以加：

- DataTable Lookup
- Struct Break / Make
- Enum Switch
- Async Task
- Timer
- Interface Message
- Delegate Bind / Broadcast

### 5.4 属性面板

选中节点时显示：

- 节点类型。
- 标题 / 显示名。
- Blueprint 原始节点名。
- 所属图：EventGraph、FunctionGraph、WidgetGraph 等。
- 参数列表。
- 每个参数是否连线。
- 每个参数默认值。
- 输出值。
- 备注。
- 风险提示。
- 来源资产路径和原始节点 ID。

选中连线时显示：

- 连线类型：Exec / Data / Comment / Reference。
- 源节点、源端口。
- 目标节点、目标端口。
- 数据类型。
- 是否来自导入。
- 是否需要人工确认。

## 6. 蓝图语义模型

本工具不需要保存 UE 蓝图所有细节，但要保存足够的“理解逻辑”信息。

### 6.1 节点

节点是逻辑单元，例如事件、调用、分支、变量读写。

节点必须有稳定 `id`，用于 AI 引用和连线恢复。显示名可以改，但 `id` 不应频繁变化。

### 6.2 端口

端口分两类：

- 执行端口：白线，表示执行顺序。
- 数据端口：带类型，表示值流向。

一个节点可以有多个输入执行线。这个能力很重要，因为 GetTheMeaning 里已经出现过“两个执行线连到同一个 Set 节点”的误读风险。

### 6.3 连线

连线保存源节点、源端口、目标节点、目标端口。

执行线和数据线必须分开保存，不能只保存“节点 A 指向节点 B”。否则会丢失参数默认值、Branch True/False、Loop Completed 等关键语义。

### 6.4 备注和注释框

UE 蓝图里的注释框很有助于理解，例如你提到的 C 键位框柱注释。第一版应该支持：

- 导入注释节点。
- 保存注释框范围。
- 把注释框内包含的节点列出来。
- 在 Markdown 里按注释组分段。

## 7. 双向工作流

### 7.1 用户画给 AI 看

1. 用户在画布上新建草图。
2. 拖出事件、分支、调用、变量等节点。
3. 连接执行线和数据线。
4. 在节点参数里填写默认值、类型、备注。
5. 导出 / 复制 `Sketch_Logic.json`。
6. 发给 Codex，让 Codex 按结构理解并给出 C++ / 蓝图实现建议。

### 7.2 AI 画给用户看

1. Codex 读取 GetTheMeaning 导出或用户描述。
2. Codex 生成 `Sketch_Logic.json`。
3. 工具打开 JSON。
4. 用户看到图、节点备注、风险提示和执行路径。
5. 用户可以手动调整，再导出给 Codex 继续分析。

### 7.3 GetTheMeaning 导入

导入 GetTheMeaning 的 `*_Logic.json` 时：

- 保留 AssetPath、BlueprintName、Class、ExportTime。
- 把原始节点 ID 放到 `source.originalNodeId`。
- 把执行线导入为 Exec Link。
- 把参数连线导入为 Data Link。
- 把未连接参数和默认值导入到参数表。
- 把 Risk Summary 导入到 `riskHints`。
- 把注释框导入为 Comment Group。
- 对无法识别的节点使用 `unknown` 类型，但保留原始信息。

## 8. 输出设计

### 8.1 Sketch_Logic.json

机器可读主格式。它是工具自己的权威文件。

用途：

- 保存画布。
- AI 读取。
- 后续导入回工具。
- 作为 GetTheMeaning 和 WinUI 工具之间的桥接格式。

### 8.2 Sketch_Readable.md

人类可读摘要。

建议包含：

- 资产元信息。
- 节点总表。
- 执行路径。
- Branch True / False 路由。
- 函数 / RPC 调用参数总表。
- 未连接参数和默认值。
- 变量读写表。
- 风险提示。
- 注释组说明。

### 8.3 Mermaid

Mermaid 适合快速发给对话或 Markdown 文档，但它表达 Pin 和数据流有限。

第一版 Mermaid 只作为辅助预览，不作为权威格式。

## 9. 风险检查

这个工具可以延续 GetTheMeaning 已经开始做的风险摘要。

第一版建议支持这些风险：

- 调用参数未连接但有默认值。
- `ReturnValue` 没有被 Branch 或变量使用。
- `ForEachLoopWithBreak` 的 Break 未连接。
- Branch True / False 路由不清晰。
- 多条执行线进入同一个节点。
- RPC 调用缺少关键参数。
- Widget `CreateWidget` 没有 OwningPlayer。
- Widget 创建后未缓存引用。
- 多次 `AddToViewport` 可能重复添加。
- 成功路径传了非空错误文本。

风险提示只做辅助判断，不能当成绝对 bug。导出里应写明“需要人工确认”。

## 10. 文件落点

工具自身工作区遵守整体项目规范。建议默认：

```text

  UnrealBlueprintBridge.settings.json
  Sketches\
    <ProjectName>\
      <SketchName>\
        Sketch_Logic.json
        Sketch_Readable.md
        Sketch.mmd
        Imports\
        Exports\
  Logs\
  Backups\
```

如果用户从某个 Unreal 项目导入，建议按项目名或 `.uproject` 名分组，例如：

```text
Sketches\
  FantasyProject\
    GM_PtoP_ROC_AnyoneLogin\
```

路径保存原则：

- 工具权威数据用相对路径。
- 外部来源路径只作为只读来源记录。
- 导入的 GetTheMeaning 文件可以复制一份到 `Imports`，避免以后原文件移动导致无法追溯。

## 12. 实现阶段

### 阶段 1：工具壳和草图文件

- 按工具箱规范搭 WinUI 壳。
- 建立设置、Log、Dialog、Tips、通告栏基础。
- 定义 `SketchDocument` 模型。
- 新建 / 打开 / 保存 `Sketch_Logic.json`。

### 阶段 2：手动画布

- 节点库。
- 添加节点。
- 拖动节点。
- 选择节点。
- 右侧属性面板。

### 阶段 3：导出

- Markdown 导出。
- Mermaid 导出。
- 复制 JSON / Markdown 到剪贴板。
- 导出前保存当前草图。

### 阶段 4：GetTheMeaning 导入

- 读取 `*_Logic.json`。
- 映射常见节点。
- 导入执行线、数据线、默认值、风险提示、注释组。
- 生成初始布局。

### 阶段 5：AI 双向桥接

- 提供“从剪贴板导入 JSON”。
- 提供“复制给 Codex”的紧凑格式。
- 支持 AI 生成的 `Sketch_Logic.json` 打开。
- 支持风险摘要和修改建议作为图上标注。

### 阶段 6：Unreal 插件联动

- GetTheMeaning 增加“导出后打开连结工具”按钮。
- 或 WinUI 工具设置 GetTheMeaning 导出目录，一键扫描最近导出。
- 后续再考虑 Editor Utility 半自动创建节点。

## 13. 第一版成功标准

第一版完成后，应该能做到：

- 你能画一段 GM / PC / Widget 的登录、房间、卡牌流程。
- Codex 只看 `Sketch_Logic.json` 就能知道节点、参数、默认值和连线。
- 你能把 GetTheMeaning 导出的复杂蓝图转成一张简化图。
- 多输入执行线、Branch True/False、函数参数默认值不会被摘要误读。
- 导出的 Markdown 能直接粘贴到对话里继续分析。

后续开始实现前，建议先确认这几个选择：

2. 第一版是否只做独立 WinUI 工具，不接 Unreal 插件按钮。（）
3. 画布第一版是否接受简化视觉，不追求 UE 原版节点外观。
4. 导入 GetTheMeaning 时，是否默认复制来源 JSON 到工具工作区。
5. 第一版是否优先支持 Blueprint / Widget / C++ 摘要三类导入，还是先只支持 Blueprint `*_Logic.json`。
